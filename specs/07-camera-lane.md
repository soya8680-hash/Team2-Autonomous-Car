# 지시서 07 · 카메라로 노란 차선 따라가기

> **3조 지시서를 가져옴** (github.com/jihooni217/raspbot-pbl-3team @ 7e8a30d, 2026-11-05). 규칙과 숫자는 3조가 정한 값이고 **2조가 아직 확인하지 않았다.** 아래 「결과」 표의 기존 줄은 3조 기록이며 2조 라즈봇·트랙에서 나온 결과가 아니다.

## 목표
640×480 카메라 화면의 노란 차선 두 줄로 차선 중심을 구하고, 비례 조향으로 차선 가운데를 따라가며 영상과 계산 기록을 남긴다.

## 규칙표
| 상황 (언제) | 행동 (무엇을) |
|---|---|
| 화면 읽기 | `tools/yolo.py`의 `open_camera()`를 사용해 640×480 화면을 읽는다. 카메라는 한 스레드만 읽고 최신 화면을 공유한다. |
| 노란색 선택 | OpenCV HSV에서 H 15~40, S 80 이상, V 100 이상인 점만 고른다. 경계값을 포함한다. |
| 차선 찾기 영역 | 사용자가 지정한 120~300줄 띠를 사용한다. 파이썬 범위는 `frame[120:300]`으로 120~299행이다. 화면 높이 약 25~62.5%에 해당한다. |
| 왼쪽·오른쪽 선 계산 | 띠의 왼쪽 절반 x<320에 있는 노란 점의 x 평균을 왼쪽 선, 오른쪽 절반 x>=320의 평균을 오른쪽 선으로 본다. 선 인정 최소 노란 점 개수는 반쪽마다 50픽셀이다. |
| 두 선이 보임 | 두 선의 중간을 차선 중심으로 보고, 오른쪽 평균−왼쪽 평균을 마지막 차선 폭으로 갱신한다. |
| 한쪽 선만 보임 | 마지막으로 두 선을 함께 보았을 때 잰 차선 폭의 절반을 사용한다. 왼쪽 선만 보이면 왼쪽 평균+폭/2, 오른쪽 선만 보이면 오른쪽 평균−폭/2를 중심으로 본다. |
| 처음부터 한쪽 선만 보이고 이전 폭이 없음 | 두 선이 함께 보여 폭을 잴 때까지 정지 대기한다. 폭을 임의로 만들지 않는다. |
| 비례 조향 | 오차=차선 중심−320. 보정=K×오차, 왼쪽 바퀴(0·1)=35+보정, 오른쪽 바퀴(2·3)=35−보정. K는 0.4이다. 정수 속도로 바꾸고 바퀴별 범위 0~80으로 제한한다. 오른쪽으로 가야 할 때 왼쪽 바퀴가 빨라진다. |
| 두 선을 모두 놓침 | 마지막으로 실제 좌우 속도 차이를 주어 꺾던 쪽으로 안쪽 바퀴0·바깥쪽60으로 찾는다. 아직 꺾은 적이 없어 방향이 없으면 즉시 정지하고 재실행 전까지 재출발하지 않는다. |
| 두 선 미검출이 1초에 도달함 | 네 바퀴를 정지하고 프로그램을 다시 실행하기 전에는 자동 재출발하지 않는다. |
| 첫 화면 대기·카메라 화면 갱신 중단 | 첫 화면 전에는 정지한다. 마지막 새 화면부터 0.5초가 넘으면 정지하며 자동 재출발하지 않는다. 카메라 읽기 오류로 예외가 나도 종료 정지한다. 같은 화면을 반복해서 읽어 선을 다시 발견한 것으로 처리하지 않는다. |
| `--check` 실행 | 실제 바퀴 명령을 전혀 보내지 않는다. 정지 명령도 보내지 않는다. 카메라로 읽은 선 위치·노란 점 개수·차선 폭·중심·계산한 바퀴 값을 1초마다 출력한다. 종료에도 모터에 접근하지 않는다. |
| 화면 표시·영상 저장 | 노란 선 위치·차선 중심·화면 중심·계산한 바퀴 값을 화면에 그리고 `results/videos/`에 블랙박스로 저장한다. 영어·숫자만 사용한다. 기존 03처럼 15fps, 부족한 화면 반복으로 실제 시간과 재생 시간을 맞추고 1분마다 분할·최근 blackbox_ 파일 30개만 보관한다. |
| 아무 키나 Ctrl+C | 즉시 정지하고 종료한다. `--check`에서는 모터 명령 없이 종료한다. |
| 종료·오류 | 주행 모드에서 기존 정지 부품으로 네 바퀴 0 묶음을 0.2초 간격 3회 반복하며 바퀴 사이 0.01초 간격을 둔다. 카메라·녹화도 정리한다. |

## 성공 기준 (숫자로)
- HSV 경계값과 120~299행·좌우 반쪽 구분을 장치 없는 검증으로 확인한다.
- 두 선 평균과 중심·폭, 한 선과 이전 폭을 이용한 중심이 저장된 검증 이미지의 알려진 위치와 일치해야 한다.
- 저장해 둔 실제 사진도 읽어 선 위치·노란 점 개수·중심 계산 결과를 기록한다. 차선 정답이 없는 사진은 검출 결과만 기록하고 실제 차선 정확도로 판정하지 않는다.
- 오른쪽 오차에서 왼쪽 바퀴가 더 빨라지고, 왼쪽 오차에서 오른쪽 바퀴가 더 빨라야 한다. 기본 35, 바퀴별 최대 80, 절대 150 이하이다.
- 두 선 미검출 시 마지막 꺾기 방향0/60 탐색·1초 도달 정지 및 정지 후 자동 재출발 방지를 검증한다.
- `--check`의 1초 출력과 모든 종료 경로의 모터 명령 없음을 검증한다. 주행 모드의 키·Ctrl+C·오류 시 네 바퀴 정지 3회도 가짜 장치로 확인한다.
- 실제 바퀴 주행 성능은 이번 작업에서 판정하지 않는다. 이번 요청은 지시서·구현·장치 없는 검증까지이다.

## 안전
- 기본 속도 35, 바퀴별 최대 80, 프로젝트 절대 한계 150. 최저 속도는 0이며 후진하지 않는다.
- 실제 바퀴는 아직 실행하지 않는다. 향후 상자/바닥 시험 때 각각 사용자 안전 확인을 먼저 받는다.
- 아무 키나 Ctrl+C로 정지하며, 오류가 나도 주행 모드의 네 바퀴 정지를 3회 시도한다.
- 카메라·녹화는 주행 반복을 막지 않게 분리하고 최신 화면만 사용한다.
- 사진·영상은 Git에 올리지 않는다. 저장 사진 검증 결과표와 수치 기록만 커밋 대상으로 둔다.
- 기존 06의 사람·동시 시험은 사용자 요청대로 보류를 유지한다. 이번 기능에 YOLO·초음파 반응은 추가하지 않는다.

## 바꿔 볼 값
- HSV: H 15~40, S 80 이상, V 100 이상.
- 띠: 120~299행, 좌우 분할 x=320, 화면 640×480.
- 비례 계수 K: 0.4, 기본 속도 35, 최대 80, 최저 0.
- 선 인정 최소 점 개수: 반쪽마다 50픽셀.
- 폭 미확인 시 대기, 두 선 미검출 시 마지막 꺾기 방향으로0/60 탐색, 화면 갱신 0.5초 초과 중단 시 정지 후 재실행 필요.
- 두 선 미검출 탐색은 최대1초, 1초 도달 시 정지 뒤 자동 재출발 없음. 화면 갱신 중단은 기존0.5초 초과 정지로 구분한다.
