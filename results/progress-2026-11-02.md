# 라즈봇 1~7단계 진행 보고

## 설치 완료 후 추가 점검 (최신 상태)

- 사용자가 설치 완료를 알린 뒤 Raspbot_Lib 및 OpenCV 4.10.0 불러오기 성공. 아래 초기 보고의 설치 대기 상태는 해소됨.
- GPIO2/SDA HIGH, GPIO3/SCL LOW. 0x2b/0x0a 블록 읽기는 여전히 Errno 110.
- 6단계 servo_center.py 실행: 두 서보 명령 모두 write_array I2C error. 마지막 OK 출력은 성공 근거가 아님. 실제 정면 정렬은 미확인.
- 7단계 sensor_test.py 실행: 부저·불빛·초음파 켜기/끄기 명령에 I2C error. 초음파 거리 6회 모두 읽기 실패. 라인센서 10초 동안 읽기 실패.
- OpenCV 카메라 촬영 성공: results/camera_test.jpg (640×480, 카메라 0번). 사진 내용의 사용자 확인은 남아 있음.
- 프로그램은 종료 코드 0과 OK를 출력하지만 I2C 오류를 숨기는 드라이버 특성 때문에 센서 정상 판정 불가. 종료 시 불빛·초음파 끄기 명령도 통신 오류.
- motor_test.py 및 drive_test.py는 미실행: 통신 장애가 남고, 바퀴 띄우기 준비 완료 답도 아직 없음. teleop.py는 수칙에 따라 사용자 직접 실행 단계.
- 다음 순서: 확장 보드 분리 비교 검사 등으로 SCL LOW 원인 확인 → 센서 응답 확인 → 바퀴 띄우기 준비 확인 → 바퀴 시험 → 정면 정렬 및 센서 재시험 → 바닥 공간 확인 후 여섯 방향 주행.

## 실행 및 확인 결과

- 점검 프로그램 5개 원본 다운로드 후 Python AST 문법 검사 통과(source-check.json). 하드웨어 기능 통과를 뜻하지 않음.
- /dev/i2c-1 및 영구 i2c_arm 설정 존재. SDA HIGH, SCL LOW.
- 드라이버와 같은 방식인 read_i2c_block_data(0x2b, 0x0a, 1)가 약 1초 뒤 Errno 110으로 실패(i2c-check.json).
- USB 카메라 Integrated_Webcam_HD, uvcvideo 드라이버 인식 및 실제 사진 수신 성공. 카메라 정면 정렬은 확인하지 않음.
- sudo 드라이버 복사와 OpenCV 설치는 모두 'sudo: a password is required'로 실패. 설치 완료로 보고하지 않음.
- 제공 수칙의 모터 번호는 0~3. 앞선 임시 전진 코드의 1~4와 다르므로 재사용하지 않음. 번호 차이는 SCL LOW 및 센서 읽기 시간 초과의 원인을 설명하지 않음.

## 다음 순서

1. 사용자가 VS Code 터미널에서 관리자 비밀번호를 입력하여 아래 설치를 완료한다.

```bash
sudo mkdir -p /usr/local/lib/python3.13/dist-packages
sudo cp -r /home/pi/py_install/Raspbot_Lib /usr/local/lib/python3.13/dist-packages/
sudo apt update && sudo apt install -y python3-opencv
python3 -c "from Raspbot_Lib import Raspbot; import cv2; print('드라이버·OpenCV OK')"
```

2. I2C 통신을 복구하고 읽기 응답을 확인한다. 현재는 SCL LOW로 부품 기능을 정상 판정할 수 없다.
3. 바퀴가 바닥에서 뜬 상태라는 답을 받은 뒤 motor_test.py를 실행하고 사람이 네 바퀴의 회전을 확인한다.
4. servo_center.py 및 sensor_test.py를 실행한다. 센서 시험 전 손·검은 테이프 조작 안내와 관찰이 필요하다.
5. 바닥 사방 1m 확보를 별도로 확인한 뒤 drive_test.py를 실행하고 여섯 동작을 사람이 확인한다.
6. 사용자가 직접 터미널에서 teleop.py를 실행한다. 종료·전원 끄기는 별도 확인 후 진행한다.
